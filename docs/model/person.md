# Person 최소 도메인 모델

## 의미

Person은 현재 업무와 관계가 있거나 앞으로 지속적으로 연결될 가능성이 있어 NGSP에서 관리할 가치가 있는 사람이다.

NGSP에 Person을 등록한다는 것은 업무상 식별할 수 있고 다시 연락할 수 있는 연결점이 확보되었다는 의미다. 연락처를 모르는 사람은 아직 Person으로 등록하지 않으며 개인 메모 등의 단계에 머물 수 있다.

Person이 데이터베이스에 존재한다는 사실 자체가 업무상 관리 대상이라는 의미이므로 이를 나타내는 별도 속성은 두지 않는다.

## 필수 정보

- `displayName`
  - 업무상 사람을 식별할 수 있는 이름
  - 실제 이름을 모르면 `"건설과 담당자"` 같은 업무상 식별명을 사용할 수 있다.
  - `null`이거나 blank일 수 없다.
- `contactNumbers`
  - 최소 1개 이상의 `ContactNumber`가 필요하다.
  - 전화번호 자체의 정규화와 유효성은 `ContactNumber`가 보장한다.

데이터베이스에서 조회한 Person은 내부 식별자인 `id`와 현재 관리 상태인 `status`도 가진다.

## 선택 정보

- `name`: 확인된 실제 이름
- `email`: 확보된 이메일 주소

선택 정보가 없으면 `null`로 표현할 수 있다. 값이 제공된 경우 blank 문자열은 허용하지 않는다.

주민등록번호와 계좌정보는 Person이 되기 위한 최소 필수조건이 아니다. 이 정보를 Person 모델에 어떤 방식으로 연결할지는 후속 작업에서 별도로 결정한다.

## 현재 범위

현재 단계에서 필수 연락처는 `ContactNumber`만을 기준으로 한다. 이메일 등을 포괄하는 일반화된 Contact 구조는 실제 필요가 확인되기 전까지 도입하지 않는다.

대표 연락처, 연락처 중복 기준과 연락처의 저장 구조는 아직 확정하지 않았다.
