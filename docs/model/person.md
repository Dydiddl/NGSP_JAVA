# Person

## 목적

Person은 NGSP에서 업무상 식별할 수 있고 다시 연락할 수 있는 사람을 표현한다.

연락처를 확보하지 못한 사람은 Person으로 등록하지 않는다. Person으로 등록되었다는 사실 자체가 현재 업무에서 관리할 가치가 있는 사람이라는 의미다.

Person은 사람 자체의 식별·연락 정보를 책임한다. 근무, 고용, 퇴직, 공사 투입과 같은 업무 관계나 그 상태는 Person의 책임이 아니다.

## 정보

### 필수 정보

- `displayName`
  - 업무상 사람을 식별하는 이름이다.
  - 실제 이름을 모르면 `"건설과 담당자"` 같은 업무상 식별명을 사용할 수 있다.
- `contactNumbers`
  - 다시 연락하기 위한 전화번호 목록이다.
  - 최소 하나의 `ContactNumber`가 필요하다.

저장된 Person은 내부 식별자인 `id`를 가진다.

### 선택 정보

- `name`: 확인된 실제 이름
- `email`: 확보된 이메일 주소

선택 정보가 없으면 `null`로 표현한다. 값이 제공된 경우 빈 값은 허용하지 않는다.

## 불변조건

- `displayName`은 `null`이거나 blank일 수 없다.
- `contactNumbers`는 `null`이거나 비어 있을 수 없다.
- 연락처 목록에는 `null`을 포함할 수 없다.
- 한 Person은 동일한 `ContactNumber`를 중복해서 가질 수 없다.
- 입력 표현이 달라도 정규화된 번호가 같으면 동일한 `ContactNumber`로 판단한다.
- 연락처 목록은 Person 생성 이후 외부 변경으로 달라지지 않는다.

전화번호의 정규화, 형식 검증과 종류 판별은 `ContactNumber`가 책임진다. 서로 다른 Person 사이의 전화번호 중복처럼 여러 Person을 함께 확인해야 하는 규칙은 개별 Person의 불변조건이 아니다.

## PersonCreate

`PersonCreate`는 저장 전 등록 정보를 표현한다. Person과 동일한 식별·연락 정보 및 불변조건을 가지지만, 저장 계층이 부여하는 `id`는 가지지 않는다.
