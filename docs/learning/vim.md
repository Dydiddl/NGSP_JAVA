# Vim 기능과 IDE 기능 구분 정리

## 1. 문서의 목적

IntelliJ IDEA에서 IdeaVim을 사용하면 Vim의 편집 기능과 IntelliJ의 개발 기능이 하나의 화면에서 함께 작동한다.

이 때문에 처음에는 다음을 구분하기 어렵다.

* 어떤 기능이 Vim 자체의 기능인가?
* 어떤 기능이 IntelliJ가 제공하는 기능인가?
* 어떤 기능이 IdeaVim에서만 연결되어 작동하는가?
* 터미널 Vim에서도 동일하게 사용할 수 있는가?

이 문서는 Vim과 IntelliJ의 역할을 구분하고, IdeaVim을 사용할 때 무엇을 중점적으로 연습해야 하는지 정리하는 것을 목적으로 한다.

---

# 2. Vim의 핵심 역할

Vim의 핵심 역할은 다음과 같다.

> 키보드를 이용해 텍스트를 빠르고 정확하게 이동하고 편집하는 것

Vim은 원래 Java 프로젝트의 구조를 분석하거나 오류를 찾아주는 개발 도구가 아니다.

Vim 자체가 가장 강한 부분은 다음과 같다.

* 커서 이동
* 텍스트 선택
* 삭제
* 변경
* 복사
* 붙여넣기
* 반복
* 검색
* 치환
* 명령 조합
* 매크로
* 여러 파일과 창 관리

즉, Vim은 단순한 단축키 모음이 아니라 **텍스트를 조작하는 하나의 언어**에 가깝다.

# 3. Vim의 모드

Vim의 가장 대표적인 특징은 모드가 나뉘어 있다는 것이다.

## 3.1 Normal 모드

텍스트를 직접 입력하는 대신 이동과 편집 명령을 실행하는 모드다.

```text
Esc
```

를 누르면 Normal 모드로 돌아온다.

대표 명령:

```vim
h
j
k
l
```

```text
h : 왼쪽
j : 아래
k : 위
l : 오른쪽
```

```vim
w
b
e
```

```text
w : 다음 단어의 시작
b : 이전 단어의 시작
e : 현재 또는 다음 단어의 끝
```

---

## 3.2 Insert 모드

일반적인 에디터처럼 문자를 입력하는 모드다.

```vim
i
a
o
```

```text
i : 현재 커서 앞에서 입력
a : 현재 커서 뒤에서 입력
o : 아래에 새 줄을 만들고 입력
```

Normal 모드로 돌아가려면:

```text
Esc
```

---

## 3.3 Visual 모드

텍스트 범위를 선택하는 모드다.

```vim
v
V
Ctrl+v
```

```text
v       : 문자 단위 선택
V       : 줄 단위 선택
Ctrl+v  : 사각형 블록 선택
```

---

## 3.4 Command-line 모드

파일 저장, 종료, 치환, 설정 등의 명령을 실행하는 모드다.

```vim
:
```

대표 명령:

```vim
:w
:q
:wq
:q!
```

# 4. Vim만의 핵심 개념: 명령 조합

Vim의 가장 중요한 특징은 명령을 조합할 수 있다는 것이다.

기본 구조는 다음과 같다.

```text
동작 횟수 + 명령 + 이동 범위
```

또는:

```text
작업 명령 + 이동 명령
```

예를 들어:

```vim
dw
```

는 다음처럼 해석할 수 있다.

```text
d : 삭제한다
w : 다음 단어까지
```

따라서:

```vim
dw
```

는 현재 위치부터 다음 단어까지 삭제한다.

다른 예:

```vim
d$
```

```text
d : 삭제
$ : 줄 끝까지
```

즉, 현재 위치부터 줄 끝까지 삭제한다.

```vim
c2w
```

```text
c  : 삭제하고 Insert 모드로 전환
2w : 두 단어 범위
```

이러한 조합 방식이 Vim의 핵심이며 IntelliJ의 일반 단축키 방식과 가장 크게 다른 부분이다.

# 6. 문자 검색 이동

## 6.1 현재 줄에서 문자 찾기

```vim
f문자
```

예:

```vim
f(
```

현재 줄의 다음 `(` 문자로 이동한다.

```vim
F문자
```

현재 줄의 앞쪽에서 문자를 찾는다.

## 6.2 문자 앞까지 이동

```vim
t문자
```

예:

```vim
t;
```

다음 세미콜론 바로 앞까지 이동한다.

## 6.3 검색 반복

```vim
;
,
```

```text
; : 같은 방향으로 다시 검색
, : 반대 방향으로 다시 검색
```

이 기능은 Vim 자체의 기능이다.

AceJump와 비슷해 보이지만 역할이 다르다.

* `f`, `t`는 현재 줄 안에서 이동한다.
* AceJump는 화면 전체에서 원하는 위치로 이동한다.

# 7. 삭제, 변경, 복사

## 7.1 삭제

```vim
x
dd
dw
d$
```

```text
x  : 현재 문자 삭제
dd : 현재 줄 삭제
dw : 단어 삭제
d$ : 줄 끝까지 삭제
```

Vim에서 삭제된 내용은 기본적으로 레지스터에 저장되므로 붙여넣을 수 있다.

## 7.2 변경

```vim
cw
ciw
c$
cc
```

```text
cw  : 단어 끝까지 변경
ciw : 현재 단어 전체 변경
c$  : 줄 끝까지 변경
cc  : 현재 줄 전체 변경
```

`c`는 삭제 후 Insert 모드로 전환하는 명령이다.

## 7.3 복사

Vim에서는 복사를 `yank`라고 부른다.

```vim
yy
yw
yiw
```

```text
yy  : 현재 줄 복사
yw  : 단어 범위 복사
yiw : 현재 단어 전체 복사
```

## 7.4 붙여넣기

```vim
p
P
```

```text
p : 커서 뒤 또는 아래에 붙여넣기
P : 커서 앞 또는 위에 붙여넣기
```

# 8. 텍스트 객체

텍스트 객체는 Vim의 가장 강력한 기능 중 하나다.

텍스트 객체를 사용하면 따옴표, 괄호, 단어, 문단 등의 내부나 전체를 하나의 범위로 다룰 수 있다.

## 8.1 단어

```vim
iw
aw
```

```text
iw : 단어 내부
aw : 단어와 주변 공백
```

예:

```vim
ciw
```

현재 단어를 삭제하고 새 단어를 입력한다.

## 8.2 따옴표

```vim
i"
a"
```

예:

```vim
ci"
```

큰따옴표 안의 내용만 변경한다.

다음 코드에서:

```java
String name = "심성우";
```

커서가 따옴표 안에 있을 때:

```vim
ci"
```

를 누르면 `"심성우"`의 내용만 삭제되고 Insert 모드로 전환된다.

## 8.3 괄호

```vim
i(
a(
```

또는:

```vim
ib
ab
```

예:

```vim
ci(
```

괄호 안의 내용을 변경한다.

```vim
da(
```

괄호와 괄호 안의 내용을 모두 삭제한다.

## 8.4 중괄호

```vim
i{
a{
```

코드 블록 내부를 선택하거나 변경할 때 사용할 수 있다.

## 8.5 문단

```vim
ip
ap
```

```text
ip : 문단 내부
ap : 문단과 주변 공백
```

## 9.1 마지막 변경 반복

```vim

```

점 명령은 마지막 편집 작업을 반복한다.

예를 들어:



을 누르면 같은 변경 작업이 반복된다.

점 명령은 Vim을 효율적으로 사용하는 데 매우 중요한 기능이다.


```vim
5j
```

다섯 줄 아래로 이동

```vim
3w
```

세 단어 앞으로 이동

```vim
10x
```

문자 열 개 삭제

## 10.1 앞으로 검색

```vim
/검색어
```

예:

```vim

```

## 10.2 뒤로 검색

```vim
?검색어
```

## 10.3 검색 결과 이동

```vim
n
N
```

```text
n : 같은 방향의 다음 결과
N : 반대 방향의 다음 결과
```

## 10.4 현재 단어 검색

```vim
*

```


특정 변수나 메서드가 현재 파일에서 어디에 사용되었는지 빠르게 확인할 때 유용하다.

다만 이 검색은 단순한 문자열 검색이다.

IntelliJ의 `Find Usages`처럼 코드의 의미를 분석하지는 않는다.

# 11. 치환 기능

현재 줄에서 변경:

```vim
:s/기존값/새값/
```

현재 줄의 모든 항목 변경:

```vim
:s/기존값/새값/g
```

파일 전체에서 변경:

```vim
:%s/기존값/새값/g
```

변경할 때마다 확인:

```vim
:%s/기존값/새값/gc
```

여기서:

```text
% : 파일 전체
s : substitute
g : 한 줄의 모든 항목
c : 변경 전 확인
```

Vim의 치환은 강력하지만 코드의 의미를 이해하지 않는다.

예를 들어 변수 이름을 바꿀 때 단순 치환을 사용하면 문자열이나 주석까지 바뀔 수 있다.

Java 변수, 메서드, 클래스 이름 변경에는 IntelliJ의 `Rename` 기능을 사용하는 것이 안전하다.

# 12. 실행 취소와 다시 실행

```vim
u
```

이전 변경 실행 취소

```vim
Ctrl+r
```

실행 취소를 되돌림

Vim은 변경 이력을 트리 구조로 관리할 수 있으며, 일반적인 에디터보다 복잡한 실행 취소 기능을 제공한다.

초기에는 다음 두 명령만 익히면 충분하다.

```text
u       : 실행 취소
Ctrl+r  : 다시 실행
```

# 13. 레지스터

Vim은 복사하거나 삭제한 내용을 여러 저장 공간에 보관한다.

이 저장 공간을 레지스터라고 한다.

레지스터 목록 확인:

```vim
:registers
```

또는:

```vim
:reg
```

## 시스템 클립보드 레지스터

```vim
"+y
"+p
```

```text
"+y : 시스템 클립보드로 복사
"+p : 시스템 클립보드에서 붙여넣기
```

IdeaVim에서 다음 설정을 사용하면 일반 복사와 시스템 클립보드가 연결된다.

```vim
set clipboard+=unnamedplus
```

## 이름 있는 레지스터

```vim
"ayy
```

현재 줄을 `a` 레지스터에 복사한다.

```vim
"ap
```

`a` 레지스터의 내용을 붙여넣는다.

레지스터는 여러 내용을 동시에 보관해야 할 때 유용하다.

# 14. 마크

마크를 사용하면 파일 안의 특정 위치를 기억할 수 있다.

현재 위치를 `a` 마크로 저장:

```vim
ma
```

`a` 마크로 이동:

```vim
'a
```

정확한 커서 위치로 이동:

```vim
`a
```

```text
'a : 해당 줄의 첫 번째 글자로 이동
`a : 저장한 정확한 위치로 이동
```

자주 오가는 코드 위치가 있을 때 유용하다.

# 15. 점프 목록과 변경 목록

Vim은 이전에 이동했던 위치를 기록한다.

이전 위치:

```vim
Ctrl+o
```

다음 위치:

```vim
Ctrl+i
```

예를 들어 검색이나 선언 이동 후 원래 위치로 돌아올 때 사용할 수 있다.

IdeaVim에서도 사용할 수 있지만 IntelliJ의 `Back`, `Forward` 기능과 일부 동작이 겹칠 수 있다.

최근 변경 위치 이동:

```vim
g;
g,
```

```text
g; : 이전 변경 위치
g, : 다음 변경 위치
```

# 16. 매크로

Vim의 매크로는 키 입력 과정을 녹화하고 반복하는 기능이다.

`a` 레지스터에 녹화 시작:

```vim
qa
```

작업을 수행한 후 녹화 종료:

```vim
q
```

매크로 실행:

```vim
@a
```

다시 실행:

```vim
@@
```

여러 줄에 같은 형식의 변경을 반복해야 할 때 매우 강력하다.

예:

* 여러 줄 앞에 같은 문자 추가
* 일정한 형식으로 코드 변경
* 반복적인 문서 형식 정리
* CSV 형태의 텍스트 수정

다만 코드 구조를 이해해야 하는 복잡한 변경에는 IntelliJ의 리팩터링 기능이 더 안전하다.

# 17. 버퍼

Vim에서 파일을 열면 파일 내용이 버퍼에 올라온다.

버퍼 목록:

```vim
:buffers
```

또는:

```vim
:ls
```

다음 버퍼:

```vim
:bnext
```

이전 버퍼:

```vim
:bprevious
```

번호로 이동:

```vim
:b 2
```

이름으로 이동:

```vim
:b PersonMenu
```

현재 버퍼 닫기:

```vim
:bd
```

IdeaVim에서는 IntelliJ의 에디터 탭과 Vim의 버퍼 개념이 함께 작동하므로 터미널 Vim과 완전히 같지는 않을 수 있다.

# 18. 분할 창

Vim은 화면을 여러 창으로 나눌 수 있다.

가로 분할:

```vim
:split
```

세로 분할:

```vim
:vsplit
```

다른 파일을 세로 분할로 열기:

```vim
:vsplit PersonMenu.java
```

창 이동:

```text
Ctrl+w h : 왼쪽
Ctrl+w j : 아래
Ctrl+w k : 위
Ctrl+w l : 오른쪽
```

다음 창으로 이동:

```text
Ctrl+w w
```

IdeaVim에서는 IntelliJ의 에디터 분할 기능과 연결되어 작동한다.

따라서 분할 창을 만드는 방식은 IntelliJ 기능을 사용하고, 분할 창 사이의 이동에는 Vim 명령을 사용할 수 있다.

# 19. Vim의 파일 관련 기능

터미널 Vim에서는 다음과 같은 명령으로 파일을 직접 관리한다.

파일 열기:

```vim
:e 파일명
```

다른 파일 열기:


# 21. IntelliJ의 기능

다음은 Vim의 기능이 아니라 IntelliJ가 제공하는 기능이다.

## 21.1 코드 의미 분석

IntelliJ는 Java 코드를 단순한 텍스트가 아니라 클래스, 메서드, 변수, 타입으로 이해한다.

대표 기능:

* 타입 추론
* 문법 오류 검사
* 컴파일 오류 표시
* 사용하지 않는 변수 표시
* null 가능성 분석
* import 분석
* 메서드 호출 관계 분석

Vim 자체는 기본적으로 이런 정보를 알지 못한다.

---

## 21.2 선언부 이동

```text
Ctrl+B
```

또는 IdeaVim에서:

```vim
gd
```

단, IdeaVim의 `gd`를 다음과 같이 설정했다면 실제 작업은 IntelliJ가 수행한다.

```vim
map gd <Action>(GotoDeclaration)
```

즉:

* `gd`라는 키 입력 방식은 Vim에서 가져왔다.
* 선언부를 정확히 찾는 기능은 IntelliJ가 제공한다.

---

## 21.3 구현부 이동

```vim
map gi <Action>(GotoImplementation)
```

`gi` 키는 IdeaVim 매핑이지만 실제 구현부 검색은 IntelliJ 기능이다.

---

## 21.4 사용 위치 찾기

```vim
map <leader>u <Action>(FindUsages)
```

이 기능은 단순 문자열 검색이 아니다.

IntelliJ가 코드 구조를 분석하여 실제로 해당 클래스, 메서드, 변수를 사용하는 위치를 찾는다.

Vim의 `*` 검색과 차이가 있다.

```text
*           : 같은 문자열 검색
Find Usages : 같은 코드 요소의 실제 사용 위치 검색
```

---

## 21.5 안전한 이름 변경

```vim
map <leader>r <Action>(RenameElement)
```

IntelliJ의 Rename은 다음을 함께 처리한다.

* 선언부
* 호출부
* import
* 관련 파일
* 코드 참조

Vim의 문자열 치환보다 안전하다.

---

## 21.6 코드 자동 정렬

```vim
map <leader>= <Action>(ReformatCode)
```

Vim의 `=` 명령도 들여쓰기를 정리할 수 있지만 IntelliJ는 Java 코드 스타일 설정을 적용한다.

---

## 21.7 import 정리

```vim
map <leader>o <Action>(OptimizeImports)
```

이 기능은 IntelliJ 전용이다.

Vim 자체는 어떤 import가 사용되는지 기본적으로 알지 못한다.

---

## 21.8 빠른 수정

```vim
map <leader>a <Action>(ShowIntentionActions)
```

IntelliJ의 빠른 수정 기능은 다음을 제공한다.

* import 추가
* 메서드 생성
* 변수 생성
* 코드 단순화
* 오류 수정 제안
* 조건문 개선
* 예외 처리 추가

이 기능은 Vim 기능이 아니다.

---

## 21.9 디버깅

다음 기능은 IntelliJ가 담당한다.

* 중단점
* 한 줄씩 실행
* 변수 값 확인
* 호출 스택
* 조건부 중단점
* 평가식 실행
* 로그포인트

IdeaVim 매핑:

```vim
map <leader>d <Action>(Debug)
map <leader>t <Action>(ToggleLineBreakpoint)
```

키는 IdeaVim을 통해 실행하지만 실제 기능은 IntelliJ의 디버거가 수행한다.

---

## 21.10 프로젝트 파일 찾기

다음은 IntelliJ 기능이다.

* 파일 이름 검색
* 클래스 이름 검색
* 메서드 검색
* Search Everywhere
* 최근 파일
* 프로젝트 구조 탐색

IdeaVim 매핑 예:

```vim
map <leader>f <Action>(GotoFile)
map <leader>c <Action>(GotoClass)
map <leader>e <Action>(RecentFiles)
map <leader>s <Action>(SearchEverywhere)
```

# 22. Vim과 IntelliJ가 결합된 기능

IdeaVim에서는 Vim의 키 입력 체계와 IntelliJ의 기능을 연결할 수 있다.

예:

```vim
map gd <Action>(GotoDeclaration)
```

이 명령은 다음처럼 나뉜다.

```text
gd
└─ Vim식 키 입력

GotoDeclaration
└─ IntelliJ 기능
```

또 다른 예:

```vim
map <leader>r <Action>(RenameElement)
```

```text
Space + r
└─ Vim의 Leader 키 사용 방식

RenameElement
└─ IntelliJ 리팩터링 기능
```

이것이 IdeaVim의 가장 큰 장점이다.

> Vim의 효율적인 키 조작과 IntelliJ의 강력한 코드 분석을 동시에 사용할 수 있다.

# 27. 터미널 Vim을 당장 사용하지 않아도 되는 이유

IdeaVim에서도 Vim의 핵심 편집 기능 대부분을 연습할 수 있다.

다음 기능들은 IdeaVim에서도 충분히 학습 가능하다.

* 모드 전환
* 이동
* 명령 조합
* 텍스트 객체
* 검색
* 반복
* 레지스터
* 마크
* 매크로
* 분할 창 이동

터미널 Vim에서 추가로 배우게 되는 내용은 주로 다음과 같다.

* 파일 직접 열기
* Vim 버퍼 관리
* 터미널과 셸 사용
* 플러그인 관리
* `.vimrc` 설정
* 외부 명령 연동
* tmux와의 조합

따라서 지금은 IdeaVim으로 Vim의 편집 방식을 익히고, 나중에 필요성이 생겼을 때 터미널 Vim을 다시 사용해도 늦지 않다.

# 28. 최종 정리

Vim은 다음을 담당한다.

> 빠른 이동, 정확한 텍스트 범위 지정, 편집 명령 조합, 반복 작업 자동화

IntelliJ는 다음을 담당한다.

> Java 코드 분석, 프로젝트 탐색, 리팩터링, 오류 검사, 디버깅, 빌드 도구 연동

IdeaVim은 두 도구 사이를 연결한다.

> Vim 방식으로 키보드를 사용하면서 IntelliJ의 개발 기능을 실행한다.

따라서 현재 가장 적절한 방향은 다음과 같다.

```text
에디터와 IDE
→ IntelliJ IDEA

텍스트 편집 방식
→ Vim

코드 탐색과 분석
→ IntelliJ 기능

키보드 조작
→ IdeaVim

프로젝트 개발
→ IntelliJ + IdeaVim
```

현재 목표는 터미널 Vim을 완전히 대체 도구로 사용하는 것이 아니라 다음 상태를 만드는 것이다.

> IntelliJ를 사용하지만 마우스 의존도를 줄이고, Vim의 방식으로 빠르게 이동하고 편집한다.
